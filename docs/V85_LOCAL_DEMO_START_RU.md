# HYDROKONTUR 360 / МАГАДАН · V8.5 локальная ролевая демоверсия

**Область:** только учебное локальное SQLite-окружение с синтетическими объектами. **Ниже инструкция, не протокол уже запущенной демоверсии.** На MacBook/другой доверенной машине все команды выполнять из корня репозитория на одной и той же версии PR #13. Публичного сервера, реальной станции, SCADA, корпоративного IdP и промышленной базы здесь нет.

## 1. Подготовка изолированной среды

Нужен Python 3.13. Сначала проверить SHA ветки и создать отдельное непубликуемое хранилище:

\`\`\`bash
git status --short
git rev-parse HEAD
python3.13 -m venv .venv
. .venv/bin/activate
python -m pip install -r server/requirements.txt
mkdir -p .local-demo
chmod 700 .local-demo

export HYDRO_PROFILE=legacy_lab
export HYDRO_DATABASE_URL='sqlite:///./.local-demo/hydrokontur-v85.sqlite'
export HYDRO_JWT_SECRET="$(python -c 'import secrets; print(secrets.token_urlsafe(48))')"
export HYDRO_AUDIT_SECRET="$(python -c 'import secrets; print(secrets.token_urlsafe(48))')"
export HYDRO_ALLOW_DEMO_SEED=YES
\`\`\`

Не запускать на существующей или промышленной БД. Сгенерированные пароли для сессий не должны попадать в коммиты, браузерную консоль или общедоступные логи. Файл БД хранить только локально; при переносе не выдавать его за защищённую PostgreSQL/RLS-систему.

## 2. Первоначальные данные и роли

\`\`\`bash
PYTHONPATH=server python -m hydro_api.seed_lab
\`\`\`

Seed отказывается работать без \`HYDRO_ALLOW_DEMO_SEED=YES\`, принимает только SQLite и отказывает при непустой организации. Он создаёт **ровно один синтетический tenant**, семь аккаунтов (2 инженера, 1 экономист, 1 руководитель, 2 аудитора, 1 наблюдатель) и три разные \`LAB_REFERENCE\` карточки:

| ID | Для чего | Что не означает |
| --- | --- | --- |
| \`synthetic-feeder-a\` | Учебная электросеть 20 кВ | Не схема действующей сети |
| \`synthetic-cascade-upper\` | Верхняя условная ГЭС | Не реальные отметки и расходы |
| \`synthetic-cascade-lower\` | Нижняя условная ГЭС | Не эксплуатационный режим каскада |

Скрипт печатает **одноразовые случайные пароли в локальный терминал**. Их нужно сохранить приватно. Повторный seed в той же БД должен завершиться отказом, а не продублировать данные. Эти пароли не отправлять в чат.

## 3. Запуск только на localhost

\`\`\`bash
PYTHONPATH=server python -m uvicorn hydro_api.asgi:app \
  --host 127.0.0.1 --port 8000 --no-access-log
\`\`\`

В личном браузере открыть **http://127.0.0.1:8000/lab**. Контрольный endpoint \`http://127.0.0.1:8000/v71/meta/readiness\` должен прямо показывать \`sqlite_lab\`, \`production_ready=false\`, \`corporate_idp_verified=false\`.

Не использовать \`--host 0.0.0.0\` и не создавать публичный туннель без отдельного security-review: локальная JWT-демонстрация не является защищённой продакшн-аутентификацией.

## 4. Браузерная ручная приёмка (не заменяет автоматизацию)

1. Войти как инженер и убедиться, что доступна одна синтетическая организация, три отдельные карточки объектов и учебные данные.
2. Открыть раздел «15. Сценарный водный баланс двух ГЭС». При первом входе верхний объект должен быть \`synthetic-cascade-upper\`, нижний — \`synthetic-cascade-lower\`. При изменении верхнего объекта нижний не должен дублировать его.
3. Нажать «Подготовить учебный каскад», проверить входной JSON и затем «Проверить баланс». Осмотреть dry/central/wet, объёмы, напор, ограничения и SHA. Никаких объявлений реальной генерации.
4. Войти **в другом профиле браузера** как аудитор, воспроизвести те же данные и сопоставить хеши результата.
5. Проверить роли экономиста, руководителя и наблюдателя, отсутствие доступа к инженерному POST-расчёту, правильные состояния отказа. Проверить ограничения чужой организации **в отдельной тестовой базе/фикстуре**, а не предполагать, что в стандартном seed есть вторая организация.
6. Изменить параметры так, чтобы превысить rated power: итоговая энергия обязана стать \`null\`. Проверить, что нет кнопок диспетчеризации и финансовых проводок.
7. Повторить ручной маршрут на 375/390/768/1440 px и клавиатурой, зафиксировать скриншоты, реальные ошибки JS/HTTP и текст ошибок, устранить дефекты, повторить на том же итоговом SHA.

## 5. Машинные тесты и выпуск

\`\`\`bash
PYTHONPATH=server python -m pytest -q -ra -o xfail_strict=true server/tests_v85
node --check server/ui/ui.js
npm test --prefix v6-client
\`\`\`

Эти команды нужно **фактически исполнить** и сохранить JUnit, SHA и журнал, прежде чем заявлять PASS. Отдельный обязательный GitHub CI включает один полный Python-прогон без исключения исторического seed-теста; при order-dependent зависании он обязан завершиться FAIL. Нативная PostgreSQL17/RLS, внешняя система OIDC/MFA, реальная браузерная автоматизация, авторизованные данные Магаданской области и инженерная экспертиза остаются самостоятельными HOLD.
