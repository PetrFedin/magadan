# V7.3 — изменения, исправления и открытые блокеры

## Разработано

- Радиальная симметричная AC-модель до 16 узлов и 48 временных окон, контроль сложности и граничных условий.
- Контроль балансов активной/реактивной мощности и сверка узловых уравнений KCL независимо инициализированным численным методом; не внешний промышленный эталон.
- Строгая проверка физической сопоставимости базового и альтернативного варианта: те же узлы/связи/нагрузки/периоды/напряжения; допустимое изменение только параметров ветвей.
- Сквозной расчёт из физической экономии электроэнергии в годовые денежные потоки и NPV по трём условным значениям стоимости энергии. Поддерживаются отрицательная экономия и отрицательная приведённая стоимость.
- Лабораторный API для отдельных технических запусков, финансового досье, списка, сопоставления, воспроизведения и чтения по ролям.
- Привязка материалов к организации, объекту, источнику `SYNTHETIC-*`, хешам результата и исходного кода; отдельная роль экономиста.
- Ограничение повторного использования кода эффекта и одной пары сценариев внутри одной организации. Не претендует на межмодульную финансовую дедупликацию реальных корпоративных отчётов.
- Проверки против искусственного повышения статуса до промышленного согласования.
- Кандидатная SQL-миграция 070 с FORCE RLS, составными ключами, защитой от изменения записей и дополнительными `CHECK`, которые запрещают иное значение исследовательского статуса или использование несинтетических цен.
- Интерфейс серверной лаборатории с новым разделом «Радиальная сеть → Экономика»; статическая QA 1440/768/375. Не засчитывать как HTTP E2E.
- Детерминированная регрессия 145 Python и 63 JavaScript; дополнительный прогон 64 синтетических топологий; трассируемый расчётный JSON.

## Исправленные дефекты/проверки

- Boolean-значения вместо нагрузки/цены отклоняются валидатором, не приводятся к числам.
- Слишком малое сопротивление, циклическая топология, чрезмерный объём расчёта и отрицательные/NaN входы блокируются до решателя.
- Финансовое досье невозможно создать для пары с изменённой нагрузкой, иным окном времени или другой структурой сети.
- Второй расчёт сохраняет собственные входы и версии, а не заменяет контрольную модель.
- Дублирование эффекта и повторное оформление той же пары сценарием не создаёт новых финансовых результатов внутри одной организации.
- Оборудование в статусе, отличном от лабораторного, не может участвовать в синтетической модели.
- NPV остаётся отрицательным, если в модельном сценарии издержки превышают предполагаемый эффект.

## НЕ реализовано/НЕ доказано

- Реальная PostgreSQL 17 RLS: тестовый PostgreSQL и psycopg недоступны, нативный тест завершился `NATIVE_ACCEPTANCE_BLOCKED`.
- Корпоративные OIDC/MFA и личные полномочия; только тестовые протоколы входа.
- Независимое внешнее WORM-хранилище; есть проект доставки и квитанций, но нет промышленной проверки.
- Подключённая магаданская электрическая сеть: не получены лицензированные данные, схема, права доступа и независимое заключение.
- Многосвязная сеть, трансформаторы, несимметричные фазы, РЗА, аварийный анализ N−1 и проектная документация на СМР.
- Подтверждённый рыночный тариф, официальная смета и проверенная экономия.
- Промышленная математическая проверка остальных пяти отраслевых модулей.
- Конечная HTTP-браузерная E2E-проверка на рабочем сервере; локальный Chromium заблокирован административной политикой.
- Публикация кода в GitHub и production: **ничего не изменялось**.

## Решение о выпуске

Разрешить только локальную исследовательскую сборку/передачу исходного кода с флагом `production_ready=false`. Запретить обещание эффекта или использование для реальных команд на энергетических объектах. Следующий P0 — нативный PostgreSQL 17 + RLS + конкурентные транзакции в выделенной тестовой среде, затем независимый отраслевой эталон, санкционированный владелец магаданских данных и финансовая методика предприятия.
