# HYDROKONTUR 360 — V8.9.2: контроль криптографической целостности доказательств

**Состояние: исключительно синтетическая QA-лаборатория. Корпоративный staging, реальные энергетические данные, действительные разрешения правообладателей, N−1 и production — HOLD.**

## Цель

Добавлена проверка **байтового оригинала тестового файла** относительно заявленного SHA-256 и проверка двух Ed25519-подписей. Устраняется риск, когда анкета с произвольной ссылкой на документ ошибочно трактуется как доказательство его целостности. При этом **проверка подписи ключом синтетического доверенного реестра не удостоверяет должностные полномочия реального владельца энергетических данных и не даёт лицензии на их обработку**.

Файлы:
- `server/hydro_api/evidence_integrity_v89.py` — строгая схема Pydantic и независимый от API/БД алгоритм сверки файла, двух подписей и доверенного списка ключей.
- `scripts/v89_evidence_preflight.py` — офлайн-CLI, который создаёт только синтетическую квитанцию, либо возвращает отказ.
- `server/tests_v89/test_evidence_integrity_v89.py` и `server/tests_v89/test_evidence_cli_v89.py` — негативные и положительные тесты.
- `.github/workflows/v89-source-quarantine.yml` — при наличии GitHub runner требует не менее **76 PASS, 0 SKIP** на exact SHA (49 предыдущих + 27 новых).
- `.github/workflows/v84-full-regression.yml` — монолитный минимум **480 PASS** (453 прежних + 27 новых), но это только ожидаемый рубеж, пока CI фактически не исполнен.

## Схема проверки и защита от самоподтверждения

Контракт `V89-SYNTHETIC-EVIDENCE-1` включает `claim_id`, `source_id`, `source_revision`, `recorded_forecast_revision`, имя файла `SYNTHETIC-*.json/csv/txt/bin`, его размер и SHA-256, срок действия, идентификатор синтетического разрешения, идентификаторы двух разных публичных ключей.

Проверка требует:
1. **Независимо закреплённый** SHA-256 реестра публичных ключей в переменной `HYDRO_V89_PINNED_TRUST_SHA256`. При отсутствии или несовпадении — немедленный отказ. Значение нельзя брать из проверяемого манифеста, его должен предоставить отдельный контролируемый процесс.
2. **Один раз** прочитанный доверенный JSON: вычисление закреплённого SHA-256 и разбор политики используют одинаковый буфер байтов из одного файлового дескриптора; повторного открытия между этими операциями нет. Это закрывает обнаруженное окно подмены файла между разбором и хешированием. Манифесты с символическими/жёсткими ссылками, изменениями при чтении и неприемлемым размером отклоняются.
3. Два разных ключа из уже доверенного тестового реестра: `SYNTHETIC_OWNER` и `INDEPENDENT_TEST_REVIEWER`. Подписывается одинаковый канонический claim, но с разными префиксами домена `HYDROKONTUR-V89-OWNER-EVIDENCE` и `HYDROKONTUR-V89-REVIEWER-EVIDENCE`.
4. Валидные даты UTC, отдельные время выдачи и срок действия, не более 31 суток действия, запрет просроченного доказательства.
5. Обычный файл под отдельным реальным каталогом; отклонение symlink, hardlink, недопустимого имени, непригодного типа файла, слишком большого размера. Чтение ограничено 2 MiB, SHA-256 подсчитывается по реальным байтам, изменение статуса файла при чтении приводит к FAIL.
6. Отсутствие дубликатов `claim_id`, `source_id`, имени файла в проверяемой группе.
7. Создание **нового** файла квитанции с доступом 0600 и отказом при попытке перезаписи.

В квитанции явно возвращаются `real_source_rights_verified=false`, `real_source_owner_authority_verified=false`, `n_minus_one_independently_verified=false`, `real_available_capacity_mw=null`, `investment_decision=HOLD`, `production_ready=false`, `receipt_is_worm_record=false`.

**Это не WORM-система и не PKI предприятия.** Доверие к ключу и отдельность рецензента в этом выпуске — лишь тестовые роли в подготовленном доверенном реестре. Нельзя использовать квитанцию для фактического допуска реальных данных.

## Тестирование

В отдельном доступном Python-контейнере (Python с `cryptography`, `pydantic`, `pytest`) выполнено **27/27 изолированных тестов PASS**, в том числе проверены замена байтов при одинаковом размере, неправильная подпись и роль, чужой или подменённый реестр, просрочка, отсутствие закреплённого доверенного хеша, symlink/hardlink/path traversal, отсутствие перезаписи квитанции. **Это не GitHub-hosted CI, не полная регрессия приложения, не PostgreSQL17/OIDC/MFA/Chromium и не проверка реальной схемы сети.**

Команда для повторения внутри репозитория:

```bash
PYTHONPATH=server python -m pytest -q -ra -o xfail_strict=true \
  server/tests_v89/test_evidence_integrity_v89.py \
  server/tests_v89/test_evidence_cli_v89.py
```

Вызов CLI (только для синтетических, локально созданных тестовых файлов; публичный ключ и сам подписанный манифест не создаются из реальных документов):

```bash
# SHA доверенной политики должен приходить из ОТДЕЛЬНОГО защищённого источника.
export HYDRO_V89_PINNED_TRUST_SHA256='<64 hex, approved outside the manifest>'
python scripts/v89_evidence_preflight.py \
  --signed-manifest /secure/synthetic/signed.json \
  --pinned-trust-policy /secure/synthetic/trust.json \
  --synthetic-data-dir /secure/synthetic/files \
  --receipt /secure/synthetic/receipt.json
```

*Пути приведены как образец. Нельзя заполнять их внутренними документами Магаданской энергосистемы.*

## Следующие обязательные инженерные рубежи

- Раздельный защищённый storage для прав владельца и версионирования документов; отзыв доверенных ключей, процесс назначения рецензента, контроль разрешённой цели обработки.

- Реально **исполняемый** CI на одном SHA, нативный PostgreSQL17/RLS, корпоративный OIDC/MFA, браузерная и security-приёмка. До этого `main`, production, доступная мощность и инвестиционный допуск — HOLD.
