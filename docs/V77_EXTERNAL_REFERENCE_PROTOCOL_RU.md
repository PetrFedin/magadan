# Контракт стороннего электротехнического расчёта | V7.7

## 1. Цель

Для синтетического радиального участка проверить совпадение результатов собственного симметричного трёхфазного AC PQ-решателя и другого расчётного инструмента. Контракт фиксирует данные, а не выдаёт соответствие реальным сетям. **Степень доказательности: численная сверка без подтверждения личности исполнителя и подлинности внешнего запуска.**

## 2. Состав запроса

- Канонизированный `reference_case`, `case_sha256`, `study_id`, `source_input_sha256`.
- Напряжение источника (кВ линейное), `min_voltage_pu`.
- Узлы и направленные связи: `node_id`, `parent_id`, активная и реактивная нагрузки (МВт, Мвар), `r_ohm_per_phase`, `x_ohm_per_phase`, допустимый ток (А).
- Временные окна `name`, `scale`, `hours`. Окна не должны автоматически превращаться в почасовой график фактической нагрузки.

Запрос возвращается API с `not_field_approved=true`. Пример: `examples/reference_request_v77.json`.

## 3. Состав ответа

`scope='SYNTHETIC_UNATTESTED_REFERENCE_ONLY'`, `claimed_tool`, `claimed_tool_version`, `calculation_method`, `source_reference`, `case_sha256`, массив `windows`, в каждом — суммарные активные потери МВт и точный набор узлов с напряжением pu, током А и потерями МВт.

Отсутствующие или лишние окна/узлы отклоняются. Сумма потерь по ветвям должна согласовываться с суммой по сети. Boolean, NaN, Infinity и фиктивная метка `industrial_approval_eligible=true` запрещены схемой.

## 4. Численные критерии только для лабораторного сравнения

| Показатель | Допустимое расхождение, демонстрационная политика |
|---|---|
| Напряжение узла | не более `0,0005 pu` |
| Ток ветви | `0,01 А + 0,5% × max(|I1|,|I2|)` |
| Потери ветви | `0,00001 МВт + 0,5% × max(|P1|,|P2|)` |
| Суммарные потери | `0,00001 МВт + 0,5% × max(|P1|,|P2|)` |

Эти пороги — **внутренняя тестовая политика**, не допуск энергетического регулятора или согласованная с «РусГидро» инженерная норма. Для реального проекта предельные погрешности устанавливаются в программе независимой верификации до испытаний.

## 5. Запуск отдельно установленного pandapower

Подготовлен `scripts/run_external_pandapower_v77.py`. Он переносит в pandapower симметричные PQ-нагрузки и линии без ёмкостных шунтов с расчётной длиной 1 км. Требуется отдельно установленный и согласованный pandapower.

```
python scripts/run_external_pandapower_v77.py \
  --request examples/reference_request_v77.json \
  --output artifacts_v77/pandapower_submitted_reference.json
```

В текущем окружении библиотека не установлена, поэтому скрипт **не запускал настоящий pandapower** и корректно завершился `PANDAPOWER_NOT_INSTALLED` без генерации ложных данных. Поддельная копия внутренних результатов в `reproducible_trace_v77.json` служит только проверке транспортного контракта.

## 6. Перенос на объект Магаданской области

**G0 — право на данные:** договор и перечень разрешённых величин. **G1 — схема:** утверждённая действующая топология и приборы. **G2 — корректность:** синхронизация измерений, единиц, пропусков. **G3 — эталон:** запуск другого отраслевого решателя специалистом с протоколом версии ПО и кода. **G4 — сопоставимость:** одинаковые начальные граничные условия. **G5 — расчёт:** отчёт расхождений и неопределённости. **G6 — независимый инженер:** заключение с ограничениями. **G7 — экономист:** отдельная оценка, не подменяющая инженерный допуск.

Ни один из этих G0–G7 для действующей сети Магаданской области в V7.7 не завершён.
