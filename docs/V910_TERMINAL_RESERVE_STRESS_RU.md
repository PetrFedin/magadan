# HydroKontur 360 — V9.10: условный резерв воды, дополнительная нагрузка и граница зимнего дефицита

**Редакция:** 18.11.2026. **Исследовательский модуль**, не расчёт разрешённых режимов Колымского каскада, не инвестиционный расчёт, не N−1. Все эксплуатационные, коммерческие, инвестиционные и production-допуски — **HOLD**.

## 1. Что именно проверяем

У V9.9 [Draft PR #34](https://github.com/PetrFedin/magadan/pull/34) при сравнении двух эвристик расчётный месячный дефицит отсутствовал во всех **216 выбранных** комбинациях; при этом в 213 парах различались холостые сбросы и во всех 216 вариантах hydro-first оставлял меньше воды к концу сезона. Эти факты **не говорят о реальной мощности и вероятности отсутствия дефицита**.

V9.10 проверяет, как изменится картина, если одновременно:

- в каждом месяце удерживать заданную *условную долю полезного объёма*, которую нельзя пропускать через турбины;
- варьировать начальное заполнение водохранилищ;
- сокращать доступную в сценарии тепловую мощность;
- добавлять к исходной постоянной нагрузке условную промышленную нагрузку;
- учитывать две старые эвристики **thermal-first / hydro-first**;
- повторять месячные исторические 5% / 50% квантили притока, **не выдавая** их комбинации за полноценные связанные гидрологические годы.

## 2. Нормативный контекст и числовые расхождения

[Приказ Росводресурсов №174 от 07.07.2025](https://www.consultant.ru/document/cons_doc_LAW_511518/2ff7a8c72de3994f30496a0ccbb1ddafdaddf518/), зарегистрирован 01.08.2025 №83126, заменил приказы 2023 года. В [разделе V](https://www.consultant.ru/document/cons_doc_LAW_511518/5673eaa309e086a26fdf97537ddb8f3896ae2603/) опубликованы полезные объёмы **7,239 км³** (Колымское) и **2,573 км³** (Усть-Среднеканское), нормальные подпорные уровни, УМО и другие параметры. В устоявшихся V9.7–V9.9 входных допущениях использованы **округлённые 7,24 и 2,57 км³**; V9.10 оставляет эти значения, чтобы сохранить контрольные хеши/сопоставимость, но отдельно фиксирует расхождение: +0,001 и −0,003 км³ соответственно.

Поскольку нормативный **уровень** не равен постоянной доле полезного **объёма**, сценарные ограничения V9.10 в 0/10/25% **НЕ** являются законными или гидрологически допустимыми резервами. До перевода в операционную модель необходимо извлечь разрешённые геометрические зависимости уровня от объёма, кривые нижнего бьефа, обязательные попуски, допустимые сезонные режимы, согласовать расчёты по редакции и правам.

## 3. Метод: резерв активного полезного объёма

В отдельном модуле \`server/hydro_api/terminal_reserve_v910.py\` применён **адаптер** к уже проверенному V9.9 движку. Старый \`winter_energy_balance_v9.py\` восстановлен **побайтно**, чтобы не менять источники старого артефакта.

Для каждого водохранилища с исходной ёмкостью полезной воды \`C\`, начальной условной долей \`f0\`, нижней постоянной сценарной долей \`r\` (\`0 ≤ r < f0 ≤ 1\`):

\`\`\`
C_active = C * (1 - r)
f_active_initial = (f0 - r) / (1 - r)
S_absolute[t] = S_active[t] + C * r
\`\`\`

Такой сдвиг нуля активного объёма не меняет уравнение сохранения воды; он ограничивает **турбинные выпуски**, сохраняя неизымаемую часть полезного объёма. На каждом шаге проверяются верхняя/нижняя границы **абсолютного** запаса, энергетический баланс и невязка общей массы каскада.

**Ограничение метода:** постоянная нижняя граница действует **на каждый месяц**, а не только на конец апреля. Значит, V9.10 — более строгая сценарная граница, **не** решение задачи с одним терминальным ограничением. Реальные пороги по уровням, переменный напор, полезная/мертвая ёмкость, инерционность ТЭС и задержка воды между ступенями здесь отсутствуют. При \`f0=r\` расчёт отказывает, вместо подстановки псевдоположительного \`ε\`.

## 4. Три сценарных контрфакта, без двойного приписывания дефицита

Для одного и того же исходного стока, мощности ТЭС, начальной воды и политики запускаются три независимых расчёта:

1. \`baseline_with_floor\`: базовая нагрузка **574 МВт** и сценарный резерв.
2. \`stress_with_floor\`: **574 + ΔL МВт** и тот же резерв.
3. \`stress_without_floor\`: **574 + ΔL МВт** без сценарного резерва.

Рассчитываются две **подписанные разности выходов модели**:
\`Δshortfall_load = U(stress_with_floor) - U(baseline_with_floor)\`,
\`Δshortfall_reserve = U(stress_with_floor) - U(stress_without_floor)\`.

**Внимание:** \`Δshortfall_load\` не является количеством энергии, неотпущенной *конкретно новому предприятию*: разные уровни спроса могут менять модельную диспетчеризацию. Нужна отдельная договорная приоритизация нагрузки и специализированная система аллокации дефицита.

## 5. Полная синтетическая матрица

| Переменная | Исследовательские значения |
|---|---|
| Начальная доля полезного объёма | 15%, 30%, 50% |
| Минимум полезного объёма в **каждом** месяце | 0%, 10%, 25% (только \`r < f0\`) |
| Сценарная доступность ТЭС | 0, 160, 272, 320 МВт |
| Дополнительная нагрузка | 0, 100, 250 МВт |
| Независимый месячный квантиль исходного стока | 5%, 50% |
| Политика | thermal-first, hydro-first |
| Число допустимых наборов | \`(2+3+3)*4*3*2*2 = 384\` |

Все 384 набора **выбраны для исследовательского покрытия границ**; нет весов и нет вероятностной трактовки. В исследовании отдельно хранится исходный дефицит и его изменение при дополнительной нагрузке. Нельзя суммировать значения дефицита по 384 сценариям, называя это EENS.

Модель R-ArcticNET использует опубликованные исторические **месячные** показатели 1933–1981 гг. и предполагаемую помесячную долю бокового притока. Это не телеметрия ГЭС, не почасовое наблюдение, не калиброванная маршрутизация и не гарантированная физическая реализуемость.
