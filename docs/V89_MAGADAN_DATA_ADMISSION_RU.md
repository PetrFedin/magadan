**Состояние:** SYNTHETIC PRE-ADMISSION LAB. **Main, staging, production: неизменны / HOLD.** Нет доступа к АСУ ТП, SCADA, реальной телеметрии или правам владельцев данных. V8.9 не утверждает мощность подключения и не заменяет СиПР, ТУ, схему сети, гидравлику или независимую экспертизу.

## Основные различия данных

| Класс | Что можно делать сейчас | Что запрещено |
| --- | --- | --- |
| `SYNTHETIC_ONLY` | Проверка формата, часовых меток, дубликатов, физической согласованности, базовой и дополнительной нагрузки | Называть рассчитанные величины фактической мощностью Магадана |

## Контракт данных V8.9

Код: `server/hydro_api/data_admission_v89.py`. HTTP-адаптер: `server/hydro_api/data_admission_api_v89.py`. API в роли **engineer/auditor**, только в организации владельца сеанса:

- `GET /v89/meta/data-admission-readiness`;
- `POST /v89/orgs/{org_id}/data-admission/preflight`.

Input `MonthlyIntake`: `mode`, `region=MAGADAN`, `year`, `month`, `sources[]`, `nodes[]`, `connections[]`, `hourly[]`.

**Источник**: уникальный `source_id`, `source_type`, `owner_name`, `permission_basis`, `owner_document_ref`, `digest_sha256_declared`. Декларированный SHA-256 **не означает проверенную контрольную сумму**: независимое сравнение с официальным байтовым объектом не реализовано. `independently_verified=false` принудительно.

**Узел (только синтетический)**: `node_id`, `constraint_source_id`, `firm_n1_limit_mw`, `baseline_coincident_peak_mw`, `operating_reserve_mw`. Поле `firm_n1_limit_mw` — **входное допущение**, а не результат сетевого N−1 расчёта. Не подтверждает доступность по реальной линии.

**Потребитель**: `project_id`, `connection_contract_id`, `canonical_consumer_id`, `node_id`, `source_id`, `baseline_inclusion`, `baseline_reconciliation_ref`, `rated_mw`, `utilization_fraction`.

Вычисление дополнительной нагрузки допускается только при `baseline_inclusion=ADDITIONAL` и отдельной синтетической ссылке на сверку с baseline. `IN_BASELINE` также требует ссылку; его дополнительная мощность равна нулю. `UNKNOWN` или повтор `canonical_consumer_id` блокирует весь результат и не превращает сомнение в 0 МВт. Это защита **от случайного двойного учёта**, но не самостоятельное доказательство полноты реестра договоров.

**Почасовой ряд**: `node_id`, `source_id`, `timestamp_utc` (формат `YYYY-MM-DDTHH:00:00Z`), `supply_mwh`, `baseline_load_mwh`. Обязательна полная сетка *всех* UTC-часов выбранного месяца по каждому узлу. Проверяются дубликаты пары `(node_id,timestamp_utc)`, пропуски, чужие месяцы, несуществующие узлы, отрицательные значения и несоответствие заданному базовому пику.

## Условная математика (только синтетическая)

- `E_incremental_h = Σ(P_nameplate × utilization)` — **условное среднее** за час, не фактическая кривая почасового потребления.
- `baseline_deficit_h = max(0,E_baseline_h - E_supply_h)`.
- `incremental_deficit_h = max(0,E_baseline_h + E_incremental_h - E_supply_h) - baseline_deficit_h`.
- `illustrative_peak_headroom = max(0,P_firm_assumed - P_baseline_assumed - P_reserve_assumed)`.

Последний показатель **никогда не помещается в `real_available_capacity_mw`**; это поле всегда `null`. Часовой спрос новых потребителей, сетевые потоки, потери, реальные N−1, водохозяйственные правила и изменения рынка здесь не моделируются.

Если найдена критическая ошибка, `quality_pass=false`, `new_project_mw_synthetic_total=null`, `nodal_synthetic_results=[]`. Даже при синтетическом PASS остаются `investment_decision=HOLD`, `production_ready=false` и отсутствие записи в финансовые регистры.

## Контрольная матрица

1. **Provenance:** владелец, первичный документ, разрешение на анализ, область использования, период, SHA, дата получения и срок действия. Автоматическая проверка прав **не выполнена**.
2. **Grain/freshness:** каждый UTC-час по узлу, календарь високосных лет, источник и время фактической доступности измерения (последнее — отдельная будущая проверка).
3. **Uniqueness:** идентификаторы проектов, договоров, канонических потребителей, узлов, пары узел×час; решения по многоточечному присоединению — через независимую сверку, не автоматическим суммированием.
4. **Physical plausibility:** размерности, значения, существующий пик и заданный резерв; фазовая сеть/гидравлика/аварийные ограничения **не валидированы**.
5. **Independence:** ревизия baseline официального баланса, запись о включённом потребителе, подтверждение сетевой и генерирующей организации, независимый инженер.
6. **Security:** только отдельная защищённая staging-среда, корпоративный OIDC/MFA, реальное PG17/RLS, внешние WORM-квитанции; этот код **не заменяет** их.
