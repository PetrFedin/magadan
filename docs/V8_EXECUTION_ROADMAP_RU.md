# ГИДРОКОНТУР 360 / МАГАДАН — V8.1–V9.0: программа технического развития и приёмки

## Принцип
Развитие не определяется количеством страниц или экранов. Каждое изменение должно иметь (1) конкретный риск/потребность, (2) утверждённую математику и входные данные, (3) воспроизводимый тест, (4) независимую приёмку, (5) источник стоимости и (6) критерий отказа.

## P0 / V8.1 — Postgres и неизменяемые доказательства
- Запустить **изолированную** PostgreSQL 17 и восстановить схему 001–150. Применить SQL-кандидат физического графа только после независимой проверки DBA. 
- Реализовать подписанную административную процедуру создания версионированных физических границ на PG; существующий `hk_app` пока имеет только `SELECT` к новому графу. Проверить конкурентность и freeze after claim.
- Отозвать лишние права (`PUBLIC`, `hk_app`), проверить owner/BYPASSRLS и все реальные API под ролями.
- Сделать миграцию прежних экономических досье **без автоматического признания**: отчёт о конфликтах и ручная верификация каждой пары `(asset,boundary,source,year)`. До завершения не выдавать итоговую сумму по всей Группе.
- Проверить SSO/MFA, смену/отзыв полномочий, внешние архивные квитанции, резервное копирование, восстановление после сбоя. Метрика успешности — подтверждённые негативные сценарии, а не `HTTP 200`.

## P0 / V8.2 — независимая электротехническая модель
- Эталонная синтетическая радиальная схема с известной топологией и всеми единицами. Запуск реального внешнего инженерного решателя (например, pandapower/OpenDSS), фиксация входных файлов и версии инструмента.
- Сравнение напряжения узлов, потоков, токов, технических потерь, пределов применимости, устойчивости при перегрузке и некорректных данных.
- Подключение только **согласованных** и разрешённых инженерных измерений магаданского объекта, самостоятельное заключение специалиста заказчика.
- Закрытие физической границы измерений, прав и версий схемы. Если схема изменилась в периоде «до/после», расчёт блокируется до корректировки методики.

## P1 / V8.3 — HydroForecast → CascadeEconomics
- Расширить водосборные данные до научно проверяемой пространственно-временной модели, без информации из будущего.
- Отдельные прогнозные горизонты и метрики, калибровка неопределённости, многолетние сценарии водности.
- Нормальная маршрутизация по допустимым гидрологическим данным и реальным кривым; независимый эксперта и границы безопасного использования.
- Исключить прямое технологическое управление. Сценарий с нарушением нормативного ограничения должен быть отсеян ещё до оптимизации экономического результата.

## P1 / V8.4 — TurbineReliability и экономика ремонтных решений
- Объектная классификация сигналов/неисправностей/отказов, интервалы состояния и историческое ремонтное событие с независимой разметкой.
- Выделить неопределённость и последствия ложного предупреждения. Использовать вероятность отказа только там, где имеется достаточное число подтверждённых событий и статистическая калибровка.
- Экономика дефектов: требуемое обследование, варианты ремонта, ЗИП, северная логистика, стоимость простоя, баланс ремонтного бюджета. Обязательное техническое вмешательство не исключается по отрицательному NPV.

## P1 / V8.5 — HeatNet Economics
- Отраслевой решатель тепловой и гидравлической сети, независимое сравнение с действующими комплексами и измерениями.
- Единицы и структура труб, насосы/тепловые пункты, фактические внешние температуры и расход; нормализация до/после без приписывания погодных изменений эффекту ремонта.
- Разделить затраты источника, сети, муниципалитета, социальную ценность надёжности и фактические денежные потоки каждой организации.

## P1 / V8.6 — строительный HydroCAPEX
- Инженерные альтернативы → изыскания → проектные разделы → согласования → ведомость работ → WBS/CBS → график СМР → закупки → фактическая стоимость → ввод.
- Нормативные требования формируются для конкретного объекта и способа реализации. Доступные схемы из публичных карт не заменяют чертежи или инженерные изыскания.
- Для северных территорий отдельно подтверждаются геокриология, сейсмические, климатические и логистические ограничения, не «прибавленные для красоты» коэффициенты.
- Прогнозный NPV включает время капитальных затрат, дополнительные эксплуатационные расходы, налоги/тарифы (по применимости) и риски проекта. Выгода от одних физических потоков не может учитываться в разных отчетах дважды.

## P2 / V9.0 — инвестиционная и рыночная приёмка
- Протокол сравнений с действующими системами конкретных владельцев объектов — без заявления о мировом превосходстве до испытаний.
- Полный цикл: техническая проблема → альтернативы → экспертиза → утверждённые расходы → исполнение → независимое подтверждение результата.
- Отдельные коммерческие модели лицензирования, НИОКР, пилотного внедрения и строительного финансирования. Грант нельзя считать одобренным до решения грантодателя.
- Анонимизированные результаты реального пилота могут быть включены в инвесторское досье только после оформления прав на раскрытие и независимого согласования фактов.

## Полномочия и ответственность
| Решение | Кто отвечает | Кто не должен совмещать роли |
|---|---|---|
| Разрешение данных и технической схемы | Собственник и технический оператор | Разработчик не подтверждает собственные исходные данные без владельца |
| Физическая модель и ограничения | Профильный инженер, гидролог, электрик или теплотехник | Экономист не может отменить обязательные физические ограничения |
| Финансовая модель | Экономическая/финансовая служба | Разработчик не утверждает исходные цены и тарифы |
| Техническая экспертиза | Независимый эксперт или назначенная квалифицированная служба | Автор модели не подписывает собственную независимую проверку |
| Инвестиция и строительство | Уполномоченный орган и технический заказчик | Серверная роль не заменяет официальный правовой мандат |
| Послепроектная M&V | Отдельный проверяющий по утверждённому плану | Исполнитель не единственный проверяющий собственного эффекта |

**Статус V8.0:** только первые P0-компоненты представлены лабораторными реализациями; остальные являются приёмочным планом. Никаких договорённостей с объектами Магаданской области не подтверждено.
