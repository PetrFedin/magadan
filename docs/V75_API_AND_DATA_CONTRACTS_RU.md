# ГИДРОКОНТУР 360 V7.5: API и машинные контракты

**Все маршруты этого дополнения являются лабораторными.** До промышленного развёртывания не допускать реальные производственные данные, удалённое технологическое управление или финансовое утверждение.

## 1. Базовые правила HTTP

Сервер FastAPI; текущая личность определяется серверной сессией. Организация в пути `org_id` проверяется относительно прав пользователя. `engineer` вправе создать исходную исследовательскую передачу; чтение доступно разрешённым пользователям своей организации; повторное вычисление ограничено `engineer` и `auditor`. В отличие от интерфейса роль нельзя подменить отправкой тела JSON.

| Операция | Назначение | Успех | Ошибки и ограничения |
|---|---|---|---|
| GET `/v75/meta/readiness` | Показать жёсткий лабораторный статус | 200 | `production_ready=false` |
| POST `/v75/orgs/{org_id}/handoffs` | Создать неизменяемую исследовательскую передачу | 201 | 403 роль; 404 источник из иной org; 409 дубликат/несоответствие; 422 структура/физический диапазон |
| GET `/v75/orgs/{org_id}/handoffs` | Список до 100 для организации | 200 | Нельзя читать другую организацию |
| GET `/v75/orgs/{org_id}/handoffs/{handoff_id}` | Просмотр версии/контрольных сумм | 200 | 404 чужая org, 409 подмена источника |
| POST `/v75/orgs/{org_id}/handoffs/{handoff_id}/reproduce` | Повторить расчёт той же версией | 200 | 403 неуполномоченный, 409 расхождение |
| GET `/v75/orgs/{org_id}/programmes/{programme_id}/handoffs` | Связанные передачи исследовательской программы | 200 | 404 нет программы, 409 подмена источника |
| POST `/v75/orgs/{org_id}/programmes/{programme_id}/reproduce-handoffs` | Воспроизвести все связанные передачи | 200 | НЕ заменяет replay родительской программы |

Функциональные названия и фактические правила проверяются в исходнике `server/hydro_api/handoff_api_v75.py` и HTTP-тестах `server/tests_v75`.

## 2. Исследовательский запрос — `HandoffNew`

`kind`: `forecast_to_cascade` либо `turbine_to_maintenance`.

`left_study_id` обязателен; `right_study_id` обязателен **только** для `forecast_to_cascade`; `programme_id` необязателен, но если задан — источники обязаны входить в зафиксированную программу. `scope` принимает исключительно `SYNTHETIC_LAB_ONLY`.

`forecast_bridge`: синтетический сценарий часов, притока и задержки для водной модели; запрещены некорректные единицы, пропуски периодов и использование будущего факта вместо прогноза. `maintenance_bridge`: именованные альтернативы с материалами, трудом, северной логистикой, простоем, условной стоимостью часа и сроком поставки.

Пример общего каркаса для *исследовательской* передачи (UUID получаются от сервера; значения внизу намеренно только типизированный шаблон, не готовый к отправке без реальных synthetic case inputs):

```json
{
  "kind": "forecast_to_cascade",
  "left_study_id": "<UUID_SYNTHETIC_FORECAST>",
  "right_study_id": "<UUID_SYNTHETIC_CASCADE>",
  "programme_id": null,
  "scope": "SYNTHETIC_LAB_ONLY",
  "forecast_bridge": "<SEE_TYPED_SCHEMA_IN_coupling_v75.py>"
}
```

Поля точной предметной структуры необходимо читать из Pydantic-схем `server/hydro_api/coupling_v75.py`: не использовать свободный JSON без проверки. Образцы полный валидных HTTP-запросов находятся в `server/tests_v75/test_handoff_api.py` и `scripts/reproduce_handoffs_v75.py`.

## 3. Фиксация происхождения

При создании сохраняются: `org_id`, `asset_id`, `kind`, идентификаторы двух исходных исследований, типы модулей, модельный/временной сценарий, SHA-256 входа и результата каждого исходного расчёта, SHA-256 родительской программы, SHA-256 версии адаптера, неизменяемый сериализованный результат, SHA-256 досье, id инженера и запись аудита.

**Reproduce** делает больше, чем сверка SHA: повторно исполняет предметный алгоритм, сверяет результат и отвергает расхождение; при изменении исходного кода без версионированной процедуры миграции исходное исследование не переписывается.

## 4. Состояние данных и права

`research_handoffs` в SQLite имеет триггеры против штатных UPDATE и DELETE и составные ссылки на организацию и исходные исследования. Миграция PG `090_calculation_handoffs_v75.sql` содержит FORCE RLS и серверные ограничения, но **не проверена нативной СУБД**, поэтому не приписываем ей подтверждённую промышленную изоляцию.

Принцип общего API: запрет доступа по умолчанию; отказ от доверия к `org_id`, JSON-полю `role` или клиентскому текстовому статусу. Окончательное разрешение независимой инженерной проверки требует отдельной процедуры, не задекларированной данным API.

## 5. Производственная интеграция — следующая версия

Для официальной интеграции предусмотреть зарегистрированную версию и метаданные единиц, `source_issued_at`, `data_available_at`, `forecast_horizon`, неизменяемую схему событий, `idempotency_key`, надёжную транзакционную запись с outbox, reconciliation, сообщения о частичной потере данных и журнал конфликтов. Протокол обмена с корпоративными системами будет определяться отдельно, после легального доступа и обследования.
