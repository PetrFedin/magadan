# V7.6 · Инженерная математика, экономические расчёты, чувствительность и запрет фиктивного эффекта

**Область применимости:** только синтетическая исследовательская постановка; не гидродинамическая модель реальной реки, не смета энергообъекта и не разрешение диспетчерского управления.

## I. Гидрологическая интеграция

На входе: версионированный `ForecastCase` с историческим моментом выпуска и целевыми временными точками; `CascadeCase` с двумя условными ступенями; `RoutingSpecification` с постоянной времени и начальным расходом. Для каждого момента расчёта используются только прогнозные значения `lower_cms`, `predicted_cms` или `upper_cms`. `actual_cms` хранится исключительно для исторической проверки качества и не подаётся в расчёт водного баланса.

Для линейного резервуара предполагаем `S=τQout`, где `S` — условный промежуточный запас воды (м³), `τ` — постоянная времени (секунды), `Qout` — расход (м³/с). Тогда `dS/dt=Qin−Qout`.

При постоянном входящем расходе в течение шага длины Δt:

`Qout_end = Qin + (Qout_start - Qin) exp(-Δt/τ)`

`Qout_mean = Qin + (Qout_start - Qin) (τ/Δt) [1-exp(-Δt/τ)]`

`S_end = τ Qout_end`. Численная проверка: `S_start + (Qin−Qout_mean)Δt − S_end ≈ 0`.

Используем **средний расход** за шаг для упрощённого водного баланса нижней ступени. Не допускаем отрицательные расходы, нечисловые значения, повторные или разорванные временные метки и превышение ограничений исходных объектов. Для каждого сценария получаем перечень нарушений. Три границы прогноза — **не** доверительные квантили и **не** вероятностное распределение без предварительной калибровки.

**Принципиальное ограничение:** суммарная энергия при фиксированных турбинных расходах, напорах и КПД не становится оптимальной только от улучшения прогноза. Модель показывает состояние запасов и проверку ограничений, не выбирает выгодные режимы.

Для следующей научной стадии необходимы реальные кривые объём–уровень, напор и КПД, локальные притоки, водохозяйственные правила, маршрутизация с учётом геометрии, гидрологическая калибровка, сезонная и климатическая проверка, внешняя экспертиза.

## II. Инвестиционный и строительный бюджет

Исходный CAPEX передаётся **только** из неизменяемой `CapitalScreen` родительской исследовательской программы. Каждая позиция содержит WBS-код, категорию, количество, источник цены, год и зависимости от предшествующих работ. Программа проверяет годовые лимиты и исключает двойное включение резерва.

`CAPEX_y = Σ(line.quantity × line.unit_price) × (1+contingency_percent/100)`.

Для каждого года `y` (начиная с базового `y0`) вводятся явно обозначенные **условные** показатели валовой денежной ценности `B_y`, дополнительных затрат OPEX `O_y` и сценарного коэффициента `s`:

`CF_{s,y} = B_y × s − O_y − CAPEX_y`

`NPV_s = Σ_y CF_{s,y} /(1+r)^(y−y0)`.

Сценарии `low ≤ base ≤ high` заданы коэффициентами, НЕ оценками вероятности. Отсутствие дохода не превращается в нулевые затраты на работы. Грант, получение займа, возврат кредита и компенсации не включаются автоматически в независимую экономическую эффективность актива. Для реального проекта потребуются финансовые потоки с НДС, налогами, амортизацией, стоимостью финансирования, инфляцией, региональными коэффициентами, действительными договорами и тарифными правилами.

### III. Контроль двойного учёта

В пределах одной организации уникален `benefit_key`. Дополнительно уникальна комбинация `(org_id,programme_id,source_bundle_sha256)`, где исходный набор межмодульных передач фиксируется без зависимости от порядка списка. Поэтому повторное оформление того же набора источников под другим названием эффекта отклоняется. **Это только технический барьер:** даже различные источники могут относиться к одной экономической причине. Для полного учёта потребуется экономический реестр причинно-связанных эффектов и независимая проверка.

### IV. Результат сквозной синтетической проверки

Файл `artifacts_v76/showcase_trace_v76.json` формируется запуском `PYTHONPATH=server python scripts/reproduce_assurance_v76.py --out artifacts_v76/showcase_trace_v76.json`. Он содержит идентификаторы и SHA-256 источников, проверку HMAC-аудита, число воспроизведённых межмодульных расчётов и годовые NPV-сценарии. Все цифры условны. В сценарии CAPEX 3 050 000 ₽ и денежный поток за 2028–2031 годы, условные NPV отрицательны; это **правильный результат инженерно-финансовой проверки**, а не доказательство коммерческой ценности внедрения.

### V. Финансовая защита для «РусГидро»

Перед презентацией должны быть собраны: базовый вариант без проекта, физическая методика расчёта, фактическая цена энергии/экономическая стоимость потерь, стоимость каждого мероприятия, график строительства, ограничения по году, стоимость владения, бюджетное финансирование, тарифная и налоговая методика, сценарная чувствительность, документальная история согласований и метод проверки результата после реализации.

Для обязательных проектов надёжности/безопасности финансовый NPV не является единственным критерием. Нормативную обязательность подтверждает уполномоченный специалист, а не алгоритм.
