# ГИДРОКОНТУР 360 — МАГАДАН: модель безопасности V7

## Фактически реализовано

- Локальная проверка учётной записи по Argon2id; JWT HS256 со сроком 15 минут, issuer/audience, token_version; logout отзывает все текущие токены пользователя.
- Пользователь НЕ выбирает роль из интерфейса. Membership и роль проверяются сервером для каждой организации.
- Все доступы к активам, источникам, моделям, расчётам, решениям, аудиту имеют фильтр `org_id` и серверную роль.
- Исходные документы и версии моделей неизменяемы штатными приложениями: SQLite-триггеры блокируют DELETE/UPDATE. Хеш SHA-256 от серверной канонической записи.
- Принятие источника и модели требует другого пользователя с ролью auditor. Документ с неправильной схемой отклоняется.
- Каждый расчёт ссылается на проверенные версию модели и данные. Численное решение AC-модели сверяется с аналитическим выражением.
- Однонаправленный автомат согласований с версионностью, `expected_revision`, раздельным инженерным, финансовым, руководящим и аудиторским участием.
- Журнал содержит HMAC цепочку по каждой организации с последовательностью, контрольной суммой и серверным временем. Доступен API проверки целостности.
- Content-Security-Policy / no-store / запрет встраивания. Токен живёт только в памяти вкладки и не сохраняется локально.
- Нет соединения с технологическими системами, командных API для оборудования или данных предприятий.

## Принципиальные ограничения

**Не production:** База SQLite тестовая. Локальные администраторы машины и обладатели ключа подписи могут изменять или пересоздавать БД. Цепочка HMAC обнаруживает часть вмешательств, но не является WORM-журналом. Нет внешней подписи/анкера, SSO/MFA, промышленного разграничения RLS, распределённого rate-limit, HA, проверенного восстановления, эксплуатационного мониторинга, резервного копирования и аттестации по применимым требованиям. PostgreSQL-подключения блокируются кодом.

**Trust boundary:** Доступ через API не равен допуска к объектам энергетики. Подпись «проверено» означает только подтверждение лабораторным пользователем. Подлинность внешнего документа, полномочия конкретного корпоративного лица и достоверность физического источника должны независимо устанавливать ответственные организации.

## Управление ключами лаборатории

`run_local.sh` создаёт `.lab.env` локально с правом доступа 0600. Не помещать этот файл в репозиторий, скриншоты, отчёты или ZIP. Секрет аудита должен быть сохранён независимо от перезапусков. При потере ключа прежние события невозможно криптографически проверить. Внешняя промышленная ротация и аварийное восстановление ещё не реализованы.

## Контроль для перехода к промышленному пилоту

1. Заказчик утвердил список организаций, активов, ролей, прав, владельцев данных и правовое основание использования каждого класса информации.
2. Корпоративная идентификация (OIDC/SAML + MFA) интегрирована и испытана; сервисные субъекты отделены от людей. Ключи вне исходного кода в защищённом хранилище; TLS/mTLS по согласованной политике.
3. PostgreSQL RLS + `FORCE ROW LEVEL SECURITY`; политика deny-by-default; настройка контекста транзакции только после проверки membership; подключение под ролью без `BYPASSRLS`. Обязательные тесты межорганизационной изоляции на прямом SQL и при повторном использовании пула соединений.
4. Аудит пишет уполномоченный серверный компонент; право на изменение/удаление журнала недоступно приложению; выгрузки с независимым WORM-якорем и проверяемыми квитанциями.
5. Обязательные идемпотентные операции, защита от повторных запросов, ограничение частоты и размера, тайм-ауты, защита от некорректных вложений и архивов.
6. Пентест, SAST, DAST, dependency scan, SBOM, сканирование секретов, моделирование угроз и утверждённые требования эксплуатационной безопасности.
7. Отдельная проверка безопасности и инженерная экспертиза до получения реальных сведений о критической инфраструктуре.
8. Независимые испытания математической модели на согласованных эксплуатационных данных. Запрещено управлять технологическими системами через ГИДРОКОНТУР.

Ориентиры: [OWASP Authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html), [FastAPI JWT](https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/), [PostgreSQL RLS](https://www.postgresql.org/docs/current/ddl-rowsecurity.html).
