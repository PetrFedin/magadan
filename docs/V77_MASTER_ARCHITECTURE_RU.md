# ГИДРОКОНТУР 360 — МАГАДАН | Техническая архитектура V7.7

**Стадия:** контролируемая синтетическая лаборатория. **Не** производственная АСУ ТП, не инвестиционное разрешение, не результат реального испытания энергетических объектов Магаданской области. Материал — внутреннее инженерное задание; все права на реальные исходные данные требуют отдельного подтверждения.

## 1. Принципы архитектуры

1. **Физический расчёт:** воспроизводимый алгоритм; входы, единицы и ограничения однозначно фиксируются.
2. **Прогноз:** момент доступности данных не позднее момента прогноза; реальный факт не может попасть в исторический прогноз.
3. **Происхождение:** `organization → asset → observation → study → handoff → programme → WBS → assurance`.
4. **Права:** сервер проверяет организацию и роль на каждом запросе; переключение селектора в браузере не заменяет авторизацию.
5. **Согласование:** инженерная проверка, экономический расчёт и полномочное утверждение — самостоятельные события. Синтетические исследования не включаются в официальный процесс автоматически.
6. **Экономический эффект:** WBS — единственный источник CAPEX в годовом DCF; дубли эффектов блокируются; нет доходов от гипотетических грантов.
7. **Безопасность:** только данные в разрешённом контуре, без командного доступа к затворам, генераторам, сетевой автоматике и диспетчеризации.

| Модуль | Проверено в лаборатории | Следующий предметный допуск |

| GridLoss Planner | Многоузловой симметричный радиальный PQ-поток, баланс, KCL, потери | Реальная топология, измерения, сторонний профильный решатель и подписанный экспертный протокол |

## 3. Новые компоненты V7.7

### GridReferenceComparisonV77

**Назначение:** сравнивать лабораторный GridLoss run с числовыми величинами, заявленными сторонним инструментом. **Не** назначает внешнего эксперта и не удостоверяет запуск стороннего программного обеспечения.

- `GET /v77/orgs/{org_id}/grid-reference/request/{study_id}`: возвращает канонизированный case и SHA-256.
- `POST /v77/orgs/{org_id}/grid-reference/comparisons`: сохраняет неизменяемый отчёт сравнения; только `engineer`.
- `GET /v77/orgs/{org_id}/grid-reference/comparisons/{comparison_id}`: чтение участником организации.
- `POST .../{comparison_id}/reproduce`: полное повторение исходного вычисления и сравнения; только `auditor`.

Результат: `LAB_NUMERICAL_MATCH_UNATTESTED` или `LAB_NUMERICAL_MISMATCH_UNATTESTED`, всегда `industrial_approval_eligible=false`.

### AnnualSensitivityV77

`GET /v77/orgs/{org_id}/assurance-packs/{pack_id}/sensitivity` доступен экономисту, менеджеру и аудитору. Он **не** записывает новую редакцию WBS: берет существующий append-only пакет и возвращает отдельный аналитический результат с такими сценариями: выгода -20/+20%, капитальные затраты +20%, неблагоприятная динамика OPEX +20%, ставка дисконтирования +3 п.п. где допустима. Включены новые бюджетные флаги для каждого сценария.

## 4. Схема доверия

`OIDC/локальная лабораторная учётная запись → Session → DB membership → asset scope → hash-pinned study → external reported data (untrusted) → numerical reconciliation → separate field review (missing)`.

Внешний результат и подпись реального инженера — разные сущности. Проверка ввода JSON не удостоверяет личность автора. SQL-триггеры не заменяют внешнюю инженерную экспертизу.

## 5. Постоянное хранение

- SQLite: используется только для локальных тестов; append-only реализован триггерами, но администратор файла способен изменить базу.
- PostgreSQL 17: кандидат `110_reference_comparisons_v77.sql` с составной привязкой организации, объекта и исходного исследования, RLS и аудитом. **Не применён нативно в данном выпуске.**
- Отдельный внешний аудит: предусмотрен ранее, производственное WORM-хранилище не подключено.
- Хеши: целостность данных внутри доверенного процесса, не доказательство источника инженерных измерений.

## 6. Непосредственная зависимость перед промышленной эксплуатацией

**P0:** реальная PostgreSQL RLS-приёмка (конкурентность, транзакционность, восстановление), корпоративный SSO/MFA, защищённый внешний журнал, запрет межорганизационного чтения при непосредственном SQL, разграничение секретов. **P0:** разрешённый объект Магаданской области, реальные измерения, схема сети, сторонний отраслевой расчёт и независимый инженер. **P1:** договора, сметы, WBS/CBS, технадзор, строительные разрешения, проверка фактического эффекта. **P2:** перенос в другие регионы только после повторной калибровки.
