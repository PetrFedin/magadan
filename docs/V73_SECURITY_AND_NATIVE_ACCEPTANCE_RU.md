# V7.3 / Нативная безопасность, эксплуатация и реестр незакрытых рисков

**Этот документ описывает испытания, которые ЕЩЁ НУЖНО выполнить.** Наличие миграции `070_grid_economic_dossiers_v73.sql` или статической проверки SQL не является подтверждением действительной PostgreSQL RLS.

## Состояние выпуска

- Локальная база: SQLite только для синтетических данных и регрессионных тестов.
- PostgreSQL: миграции 001–070 подготовлены; сервер PostgreSQL 17 и `psycopg` не запущены в текущей среде.
- Идентификация: протокол OIDC с синтетическим IdP проверялся ранее; реальный корпоративный IdP не подключён.
- Внешний архив: программная модель квитанции существует, но полноценная WORM-приёмка и внешнее хранение в регионе не проведены.
- Гидрологические/энергетические объекты: никаких действующих подключений и разрешений на данные нет.

## Нативная PostgreSQL-приёмка — обязательные кейсы

1. Использовать новую изолированную базу PostgreSQL 17. Не исполнять миграции в чужой или производственной базе.
2. Установить `psycopg`, выдать отдельные SQL-роли `hk_app`, `hk_authenticator`, `hk_exporter`, `hk_owner`; подтвердить отсутствие `BYPASSRLS` у прикладной роли.
3. Последовательно применить 001, 010, 020, 030, 040, 050, 060, 070; проверить роль владельца и FORCE RLS для каждой таблицы.
4. Без `hk_security.bind_session(...)` попытки `SELECT`, `INSERT` и изменения чужих записей должны быть запрещены.
5. При подмене `hk.org`, `hk.actor` либо при переходе между соединениями контекст не должен переноситься без подтверждённой сессии.
6. После отзыва членства и серверной сессии права должны исчезнуть даже для действующего ранее токена.
7. Прямой `INSERT` финансового досье инженером или к чужому активу должен блокироваться, даже если API недоступен.
8. Составные FK `(org_id,asset_id)` и `(org_id,run_id)` должны блокировать межорганизационную привязку.
9. `TRUNCATE`, `UPDATE`, `DELETE` для журналов/досье и изменение роли приложения должны быть запрещены.
10. В параллельных запросах к одной версии решения только одно конкурентное согласование может победить.
11. Событие, транзакционная outbox-запись и бизнес-событие должны откатываться совместно.
12. Роль экспортёра не может менять данные об активах или выдавать себе право согласования.
13. Разделить штатную доставку события и реально подтверждённую внешнюю квитанцию; не принимать поддельное заверение.
14. Провести испытание восстановления БД после аварии, повторной доставки и расхождения цепочки событий.
15. Сохранить CSV/JUnit-журнал, SHA версии кода и миграций, конфигурацию среды (без секретов) и подписи участников проверки.

**Обязательный запуск**:

```bash
HYDRO_NATIVE_TESTS_REQUIRED=1 HYDRO_NATIVE_CONFIG=/secure/path/native.json \
 PYTHONPATH=server pytest -q server/tests_v71/test_postgres_native.py
```

Если конфигурация отсутствует, тестовый процесс обязан завершиться ошибкой `NATIVE_ACCEPTANCE_BLOCKED`. Нельзя трактовать пропуск как успешное выполнение.

## Контроль отказов и DoS

- Принудительный отказ при нечисловых/неопределённых измерениях, Boolean вместо нагрузки, слишком малом сопротивлении, циклической топологии, недопустимом объёме сети.
- Лимит учебной задачи `nodes × windows <= 192`, максимум 16 узлов; пользователь не может запускать неограниченный промышленный расчёт через этот API.
- Для промышленной системы дополнительно нужны внешние лимиты запросов, очередь задач, CPU/memory quotas, мониторинг времени и контролируемая отмена долгого расчёта. Эти механизмы ещё не реализованы.
- Сохранение исходного расчёта и его результата должно иметь транзакционные границы, повторение фиксирует версию и контрольные суммы.

## Границы математики и полномочий

Наличие двух близких численных ответов доказывает лишь согласованность **двух реализаций одинаковой упрощённой модели**. Это не доказывает точность данных или корректность физического описания выбранного реального участка. Применимость требует независимого отраслевого эталона.

`SYNTHETIC_RESEARCH_ONLY_NO_APPROVAL` — не документ с юридическими полномочиями. Подача досье в промышленный инвестиционный процесс запрещена. Рабочее состояние остаётся **HOLD**.
