# Приоритеты восстановления и разработки ГИДРОКОНТУР 360

## P0.1 — Надёжно получить исходники

**Задача:** получить байты V7.9 ZIP или Git bundle. **Доказательство:** исходный архив, SHA-256 из независимой записи о выпуске, проверенный манифест файлов. Ни metadata Library, ни README GitHub не являются исходниками.

**Текущий статус:** `SOURCE_IMPORT_BLOCKED`.

## P0.2 — Перенести полный код

**Задача:** загрузить именно настоящий комплект `server/hydro_api`, `server/migrations` 001–140, `server/tests*`, `server/ui`, `scripts`, `v6-client`, примеры и технические документы. Не склеивать подлинную архивную версию со вновь написанным демонстрационным прототипом.

**Контроль:** секреты исключены, версии пересчитаны, зависимости документированы, исходные SHA-256 сохранены. Изменения при дальнейшей разработке — отдельные коммиты и новые тесты.

## P0.3 — CI и единый SHA

**Состояние:** GitHub Actions job стартовала без назначенного runner (`runner_id=0`, zero steps); первопричина не доказана. Локальные тесты инструментов восстановления прошли. Необходимо проверить доступность бесплатных runner, затем исполнить реальные Python/JS unit tests и браузерные проверки на опубликованном коммите.

## P0.4 — PostgreSQL 17 / глобальная экономическая уникальность

Выполнить миграции на **выделенной пустой тестовой БД** с физическим SQL-логом и независимыми проверками: RLS на `hk_app`, запреты между организациями, `FORCE`/owner, отзыв прав, concurrent insert/delete/rollback, re-entrant connection pool, backup/restore. Единый Benefit Ledger должен исключать дублирование физических эффектов между старой и новой схемой и внутри одного периода. SQLite не доказывает PostgreSQL RLS.

## P0.5 — Корпоративная безопасность / аудит

Проверить реальную схему OIDC + MFA + revoke, внешние подписанные WORM-квитанции, проверяемую ретенцию и восстановление. Моделирование JWT без корпоративного IdP недостаточно.

## P0.6 — Независимая физика

Изолированный внешний расчёт на реально исполняемом стороннем движке с фиксированными исходными данными, указанной версией solver, предопределёнными допусками, измерительной границей и независимым инженером. Успех внутренней математической сверки не равен полевой точности.

## P1 — Развитие остальных пяти продуктов и HydroCAPEX

Расширять HydroForecast, CascadeEconomics, TurbineReliability, GridLoss Planner, HeatNet Economics, HydroCAPEX только после восстановления проверенной кодовой базы. Сохранить формулы, размерности, версии предпосылок, расчётные тесты, документы о неопределённости и матрицу связей. Реальные экономические показатели — только из разрешённых данных с независимым заключением.

**Правило выпуска:** `SOURCE VERIFIED → CI GREEN ON SHA → native SQL/SSO/WORM → permitted field data → independent engineering/economics → authorized pilot`. До этого — лаборатория, производство на HOLD.
