## Зачем отдельные проверки

Есть два принципиально разных результата:

1. **Recovery Tool PASS:** утилита `tools/import_v79_snapshot.py` и её тестовые фикстуры отработали корректно. Это не означает наличие исходников.
2. **Source Admission PASS:** все обязательные файлы реального V7.9 уже присутствуют в GitHub, SQL-миграции согласованы и файл `SOURCE_RECOVERY_MANIFEST.json` подтверждает каждую исходную контрольную сумму. Это **только проверка происхождения, не испытание приложения**.

GitHub Actions имеет отдельные задания `recovery-tool-tests`, `source-tree-admission` и зависимую `application-regression`. Два последних остаются **blocked** до фактического переноса кода. Не отключать/пропускать `source-tree-admission`, чтобы показать зелёный CI.

## Восстановление на разрешённой машине

```bash
python tools/import_v79_snapshot.py /authorized/backup/HydroKontur_Magadan_V7_9_GitHub_Ready.zip \
  --destination /authorized/staging/hydrokontur-v79 \
  --expected-sha256 <64_hex_digits_from_independent_source>

# После проверки настоящих файлов и ручного сканирования:
# 1) отдельно зафиксировать SHA-256 самого архива из доверенного первичного источника;
# 2) отдельно удостоверить SHA-256 файла SOURCE_RECOVERY_MANIFEST.json;
# 3) передать обе сверенные величины как контрольные значения.
python -m tools.check_source_admission --root /authorized/staging/hydrokontur-v79 \
  --require-external-pin --trusted-archive-sha256 <trusted_archive_sha256> \
  --require-manifest-pin --trusted-manifest-sha256 <trusted_manifest_sha256>
```

Если независимая SHA-256 исходного архива отсутствует, импорт можно выполнить для изолированного исследования, но **CI admission не должен считаться завершённым**. Для GitHub CI передаются две проверенные SHA-256 из **внешней доверенной записи**: архив в `HYDRO_TRUSTED_V79_ARCHIVE_SHA256` и точный манифест в `HYDRO_TRUSTED_V79_MANIFEST_SHA256`. Значения не являются секретами; их должен независимо сверить reviewer с реально полученным архивом, а не просто переписать из PR. Двойной контроль нужен, поскольку самоутверждённый archive SHA в изменяемом манифесте никак не связывает содержимое файлов с архивом без проверенного SHA самого манифеста. Вычисление обеих сумм самим скриптом восстановления не доказывает их независимость.

До получения подлинного ZIP/bundle и независимого значения SHA-256 ничего не подставлять ради зелёного статуса. Миграции 001–140 нужно сверить с ранее выпущенными версиями, а не запускать на промышленной БД.
