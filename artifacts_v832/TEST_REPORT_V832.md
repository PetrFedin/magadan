## 1. Основание исправления

В исходной V8.3.1 обнаружены два воспроизводимых вычислительных дефекта:

- Оценка суточной энергии через значение уровня при среднем объёме вместо точного интеграла по кусочно-линейной кривой: `2409.493905` против `2492.237514375` МВт·ч (разница `82.743609375`) на искусственном примере пересечения узла кривой.
- Проверка номинальной мощности только по середине суточного периода: `107.84250421875` МВт при допустимом пределе `110`, хотя расчётный теоретический пик на конце суток составляет `115.2894290625` МВт. Исторический алгоритм ошибочно допускал расчёт энергии. Исправленный — `ELECTRICAL_RATED_CAPACITY_EXCEEDED`, `energy_mwh=null`.

Оба контрпримера закреплены прямыми `pytest`-регрессиями и в документации `docs/V832_ENERGY_INTEGRATION_RU.md`.

## 4. API, графика и эксплуатационные гарантии

- Пройдены тесты API двух разных LAB_REFERENCE объектов одной организации, разграничения ролей и невозможности финансовой записи, включая новый endpoint-тест отказа при превышении мгновенной мощности.
- Интерфейс явно показывает предупреждение о теоретическом пике; статическая структура и JavaScript проверены, **полноценный авторизованный browser E2E не выполнялся в этой итерации**.
- Нативный PostgreSQL 17-сервер и внешний решатель гидравлики в текущей среде не доступны. Попытка обновить apt-индексы не завершилась в доступное время; **никакой нативной PG/RLS-конкурентности не заявлять**.
- Использованы только искусственные параметры и источники `SYNTHETIC-*`; нет реальных кривых ГЭС, допусков объектов, измерений, диспетчеризации, результатов M&V, рублей или NPV.

## 5. Релизные ограничения

**Не принимать в `main`** без проверенного GitHub Actions на одном SHA, независимого инженерного ревью, штатных браузерных сценариев и нативной PostgreSQL 17/RLS/конкурентной проверки. В V8.3.2 устранены только конкретные ошибки **упрощённой суточной модельной генерации**; реальная физика требует отдельных допущений и испытаний.
