# ГИДРОКОНТУР 360 — МАГАДАН: V8.3

**Воспроизводимая лабораторная инженерно-статистическая версия. Не промышленный продукт.**

## Что изменилось

Появилась исполняемая цепочка из исходных 168 синтетических наблюдений суточного расхода V8.2 через независимый holdout к **одним будущим полным суткам** для двух связанных искусственных водохранилищ. Нижняя, центральная и верхняя границы прогноза преобразуются в отдельные, НЕ вероятностные сценарии водного баланса. Новый движок вычисляет объёмы воды в верхнем/нижнем бьефах и в пути, чистый напор, КПД и условную MWh, строго проверяя ограничения и отсутствие экстраполяции.

Выполнение расчёта не даёт распоряжений о сбросах, не формирует финансовых записей, не разрешает реальное использование данных ГЭС и не повышает уровень готовности к эксплуатации.

## Файлы и API

- `server/hydro_api/cascade_v83.py` — чистый физический движок, спецификация входных данных Pydantic и глобальный mass-balance.
- `server/hydro_api/cascade_api_v83.py` — RBAC engineer/auditor, две лабораторные карточки объектов той же организации, запрет реальных активов и серверный SHA отчёт.
- `POST /v83/orgs/{org_id}/cascade/forecast-screen` — синтетическая проверка; без записи в БД.
- `GET /v83/meta/cascade-readiness` — честные ограничения.
- `server/ui/index.html`, `ui.js`, `ui.css` — раздел 15 «Сценарный водный баланс двух ГЭС»; нужен вход и два отдельных синтетических объекта одной организации.
- `server/tests_v83/` — математические, API, UI и отрицательные тесты.
- `scripts/reproduce_v83.py` — 20 стресс-наборов × 3 прогнозные ветви + 4 нарушения ограничений.
- `artifacts_v83/` — CSV, графики, выводы проверки, контрольные суммы и результаты тестов.
- `docs/V83_CASCADE_FORECAST_PHYSICS_RU.md` — все формулы, единицы измерения, допущения и источники.
- `.github/workflows/native-v83.yml` — автоматическая синтетическая проверка (если runner доступен) + отдельная **только ручная** попытка нативной PostgreSQL17-приёмки.

## Выполнение

```bash
python -m pip install -r server/requirements.txt
PYTHONPATH=server python -m pytest -q server/tests_v83
python scripts/reproduce_v83.py --out artifacts_v83
python scripts/plot_cascade_v83.py
node --check server/ui/ui.js
(cd v6-client && npm test)
```

Техническая приёмка: **357 Python PASS, 3 SKIP, 63 JS PASS** локально. Статическая вёрстка Chromium 375/768/1440 PASS; полноценный браузерный E2E blocked. PostgreSQL17/RLS, независимая гидравлическая модель, реальная гидрология и эксплуатационный допуск не прошли.

**Важно о времени:** UTC `observed_at` — конец суточного периода. V8.3 требует `horizon_days=2` с выпуском накануне начала следующего полного прогнозируемого дня. Для `issued_at = D 10:00` целевые сутки начинаются `D+1 00:00`, заканчиваются `D+2 00:00`; это 14 часов до начала суток. Входная отметка объёма хранилища относится к началу моделируемых суток и синтетическая.

Никакие `рубли`, `NPV`, `flood probability`, `dispatch` или экономические эффекты не выдаются. Сценарии **не** представляют реальные параметры Колымской или Усть-Среднеканской ГЭС. `PRODUCTION HOLD`.

**Уточнение V8.3.1:** начальное хранение на D+1 и полные прошлые суточные выпуски включают данные из будущего относительно D 10:00. Они требуют отдельного явного признака `SYNTHETIC_CONDITIONAL_FUTURE_ASSUMPTIONS_NOT_KNOWN_AT_FORECAST_ISSUE`. Это условные сценарные исходные данные, не фактическая информация, доступная в момент выпуска прогноза.

[Сводка дополнительных лабораторных испытаний V8.3.1](artifacts_v83/TEST_REPORT_V831.md): независимое почасовое суммирование 438 случаев, явно условные будущие уровни и сбросы, обновлённые регрессионные группы.
