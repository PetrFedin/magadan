# ГИДРОКОНТУР 360 — МАГАДАН / V7.3

**Состояние 23.10.2026: ЛАБОРАТОРНЫЙ РЕЛИЗ; ПРОМЫШЛЕННЫЙ HOLD.**

Это развитие V7.2, в котором шестимодульная исследовательская платформа получила более глубоко связанный синтетический сетевой расчёт и связанную с ним экономику инвестиционной альтернативы. **Никаких реальных производственных данных, подключений АСУ ТП, подписанных допусков, внедрений или одобрений ПАО «РусГидро» нет.**

## Новое исполняемое ядро

1. `server/hydro_api/radial_grid.py`: симметричная 3-фазная радиальная AC-модель, до 16 узлов, максимум 48 окон и 192 узло-окна, строгая топология; напряжения/токи/активные и реактивные потери и контроль физического баланса. Независимая инициализация второго численного KCL-решения НЕ является внешним отраслевым эталоном.
2. `server/hydro_api/finance_evidence.py`: инвестиционный расчёт строго из ДВУХ сохранённых сопоставимых инженерных вариантов, физические MWh → kWh, три ценовых сценария, NPV, порог условной цены безубыточности. **Цены, CAPEX и OPEX искусственные; результат не является тарифной экономикой.**
3. `server/hydro_api/grid_dossiers_api.py`: лабораторные маршруты инженерного расчёта, сравнения, отдельного финансового досье и детерминированного воспроизведения. Проверка реальной серверной роли и принадлежности организации. Лабораторный актив обязателен. Запрещено продвижение в промышленное согласование.
4. `server/migrations/070_grid_economic_dossiers_v73.sql`: кандидатная PostgreSQL-миграция с RLS, составными FK, статусными CHECK, аудиторскими триггерами и запретом обновления. **Не исполнялась в PostgreSQL; может содержать невыявленные несовместимости.**
5. `server/ui/`: новая рабочая область с вводом синтетической топологии и финансов, сопоставлением сценариев, сохранением и повторением результатов. Браузерная E2E с HTTP заблокирована ограничениями среды. Лишь статическая вёрстка прошла отдельную QA.
6. Сохранены серверная логика V7.1/V7.2, шесть учебных отраслевых направлений и предыдущие тесты без объявления их промышленными моделями.

## Развёртывание только лаборатории

Требования: Python 3.13, Node 22 для старых регрессионных тестов. Для SQLite-сервера:

```bash
python -m pip install -r server/requirements.txt
export PYTHONPATH=server
export HYDRO_DATABASE_URL="sqlite:///./synthetic_v73_lab.db"
export HYDRO_JWT_SECRET="$(python -c 'import secrets;print(secrets.token_urlsafe(48))')"
export HYDRO_AUDIT_SECRET="$(python -c 'import secrets;print(secrets.token_urlsafe(48))')"
uvicorn hydro_api.main:create_app --factory --host 127.0.0.1 --port 8765
```

Приложение создаётся через `create_app`: модуль **не экспортирует** глобальную переменную `app`. Никаких адресов реальных контроллеров или корпоративных секретов в лаборатории вводить нельзя.

Тесты:

```bash
PYTHONPATH=server pytest -q server/tests server/tests_v71 server/tests_v72 server/tests_v73 \
  --ignore=server/tests/test_browser.py \
  --ignore=server/tests_v71/test_postgres_native.py
node --test v6-client/tests/domain.test.mjs v6-client/tests/assurance.test.mjs
python scripts/reproduce_showcase_v73.py
python scripts/stress_radial_v73.py
```

Нативные PostgreSQL 17 тесты только на **отдельной, новой и пустой** базе `hydrokontur_v72_*` (это наследуемое ограничение скрипта). См. `docs/V73_SECURITY_AND_NATIVE_ACCEPTANCE_RU.md` и `.github/workflows/native-v73.yml`. Workflow предоставлен как **неисполненный шаблон для ручного запуска**, не публикация в GitHub.
