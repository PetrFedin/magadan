# ГИДРОКОНТУР 360 — МАГАДАН / лабораторная сборка v0.1

Версия исследования и демонстрационного программного обеспечения: 20 октября 2026.

## Назначение и границы

Исследовательская демонстрация связей между 6 предложенными направлениями: HydroForecast, CascadeEconomics, TurbineReliability, GridLoss Planner, HeatNet Economics, HydroCAPEX. Пилот на синтетических данных. Названия Колымской и Усть-Среднеканской ГЭС приводятся только как возможные объекты будущего научно-технического согласования, **производственные данные отсутствуют**. Не подключено ни к ПАО «РусГидро», ни к ПАО «Колымаэнерго», ни к ПАО «Магаданэнерго», ни к АСУ ТП.

**Это не готовый промышленный продукт, не система управления генерацией/сетями и не прошедшее инженерную верификацию ПО.** Расчётные формулы обучающие и не заменяют технические стандарты, графики, режимные ограничения и расчёты профильных организаций.

## Состав

- `src/domain.mjs`: расчёты, состояние согласования, проверка ролей в доменной логике, запрет межорганизационных операций в клиентской модели, защита от двойного учёта эффекта, учебный журнал событий.
- `src/app.mjs`: веб-интерфейс и сценарии для шести аналитических модулей, карточки инициатив, переключение роли и организации, журнал, экспорт JSON.
- `src/styles.css`: адаптивный внешний вид (1440px / 375px).
- `index.html`: источник статического приложения.
- `build_standalone.py`: сборка автономного HTML в `dist/standalone.html`.
- `tests/domain.test.mjs`: 29 модульных проверок на Node.js.
- `tests/e2e_browser.py`: сценарии Playwright на Chromium (для исполнения необходим Playwright и Chromium); могут не работать в средах, блокирующих доступ к файлам/локальному серверу, поэтому используется инъекция содержимого в изолированную вкладку.
- `artifacts/browser_qa.json`: результаты одного локального тестового прогона.
- `artifacts/*.png`: реальные скриншоты локального отображения синтетической демоверсии.
- `artifacts/market_data.json`: 18 сравнительных досье на системы и 54 заявки на разработку. Исследование по официальным описаниям, не тест эксплуатации закрытых лицензий.
- `docs/API_CONTRACTS_DRAFT.md`: предлагаемые API и контракт верификации для следующей версии.
- `docs/ENGINEERING_VALIDATION.md`: план работы с инженерными солверами и объектами Магаданской области.

## Локальная проверка

1. Python 3 и Node.js 20+; для unit-тестов зависимости npm не требуются.
2. Выполнить `python build_standalone.py`.
3. Выполнить `node --test tests/domain.test.mjs` — ожидается 29 успешных тестов.
4. Для браузера: `python tests/e2e_browser.py` после установки Playwright/Chromium. Тест предназначен для разработчика и требует соответствующего браузерного окружения.
5. Открыть `dist/standalone.html` в современном браузере. При недоступности локального хранилища данные могут не сохраняться между обновлениями.
6. Провести отдельную проверку прав доступа, репликации данных и криптографии **перед** любой интеграцией: эти функции в лаборатории не реализованы.

## Ограничения безопасности

Переключатель «роль» — только тестовый UI и не обеспечивает реального разграничения доступа. Проверки организации только в клиентском JavaScript и не защищают данные. Сохранение происходит в localStorage, оно не конфиденциально и не серверно защищено. Контрольная цепочка событий использует SHA-256 в доступном защищённом браузерном контексте, однако не является неизменяемым журналом: владелец браузера может изменить всё хранилище и пересчитать хеши. В ограниченных браузерных контекстах выводится пометка `PREVIEW-NONCRYPTO`; это **не криптографический хеш**.

Функции удалённого управления агрегатами, автоматического принятия режимных решений, записи в диспетчерские или защитные системы отсутствуют и не должны добавляться в продуктовый аналитический контур.
